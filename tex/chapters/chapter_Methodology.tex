\chapter{Methodology}
Here we want to present the general strategies and methods that we used to develop and evaluate our implementations. We want to make clear how decisions are made for both of these processes. Moreover we want so specify what exactly this thesis wants to achieve and therefore formulate a distinct set of research questions. Details on how these strategies and goals are fulfilled are not part of this chapter so one should only get an overview here.\\
Firstly we want to find an algorithm that can calculate the set union of sets that are distributed over different processors. This algorithm should take advantage  of different representations of a subset and therefore be build like a mix of an Allreduce and an Allgather. As communication patterns differ for Allreduce/Allgather implementations where the number of processors $p$ needs to be a power of two compared to general $p$ implementations, we want to find two different variants of the algorithm. One should be only for the case if $p$ is a power of two and the other one should work for $p$ being any number. These algorithms should scale well for large sets $\tilde{S}$. This means we want an algorithm that scales at most linearly with the size $|\tilde{S}|$. These algorithms should use the different representations effectively. We want to select algorithms as foundation where expect the most benefits by switching between both representations.\\
